Get started with Beetle

Train a real bilingual model on your laptop in a couple of minutes, prepare bilingual training data from raw text to tokenised shards, and scale the same steps up to billions of tokens. Both beetlelm and beetle-data ship a download-free, CPU-only quickstart alongside the full research pipeline.

beetlelm

Train a bilingual model

beetlelm trains bilingual, monolingual and polyglot language models and stores comprehensive checkpoints for learning-dynamics research. There are two entry points: beetlelm-toy, the download-free CPU quickstart, and beetlelm-train, the full research trainer (Lightning, HuggingFace datasets, the architecture zoo, continual-learning modules). Checkpoints from both are standard HuggingFace and reload with from_pretrained.

1 · Install

bash
$ git clone https://github.com/beetlelm/beetlelm.git
$ cd beetlelm
$ pip install -e .

Full stack (Lightning, datasets, wandb, HF Hub). For the CPU quickstart only, a light install keeps the heavy training stack out:

bash
$ pip install "torch>=2.5.1" transformers numpy pyyaml click
$ pip install -e . --no-deps

2 · Quickstart (CPU, zero downloads)

bash
$ beetlelm-toy --config_path configs/tiny_cpu.yaml

…or from Python:

python
from beetlelm.toy import train
results = train("configs/tiny_cpu.yaml")
print(results["final_loss"], results["checkpoint_dir"])
Reproduce the toy result

A real model, in about 15 seconds

configs/tiny_cpu.yaml trains a 0.72M-parameter PicoDecoder for 200 steps on the in-repo bilingual (English + Spanish) byte corpus. On a laptop CPU it finishes in about 15 seconds and writes a HuggingFace checkpoint plus metrics.json to runs/tiny_cpu/.

Random loss over the 256-way byte vocabulary is ln(256) ≈ 5.55, so the drop to ~0.2 shows the model has learned the toy corpus. Runs are deterministic on CPU given the seed, and the expected numbers are committed in baselines/tiny_cpu_baseline.json. These are toy-scale sanity numbers, not research results.

Reload the checkpoint

The run writes a standard HuggingFace checkpoint you can load back in a couple of lines.

python
from beetlelm.pico_decoder.pico_decoder import PicoDecoderHF
from beetlelm.bytes import ByteTokenizerManager
model = PicoDecoderHF.from_pretrained("runs/tiny_cpu")
tok   = ByteTokenizerManager.from_pretrained("runs/tiny_cpu")

Change one variable

Everything is driven by the YAML config or by overrides / CLI flags. Point data.train_file at any UTF-8 text file to train on your own corpus.

bash
$ beetlelm-toy --config_path configs/tiny_cpu.yaml --seed 7 --max_steps 400
$ beetlelm-toy --config_path configs/tiny_cpu.yaml --d_model 256
python
from beetlelm.toy import train
train("configs/tiny_cpu.yaml", overrides={
    "model":    {"d_model": 256, "n_layers": 6},
    "training": {"seed": 7, "max_steps": 400},
})

Use the full framework

The full trainer targets larger runs on real datasets and the architecture zoo (pico, bgpt, MoE, SSM, geo-bilingual, H-Net, MambaByte), with continual-learning extensions (EWC, MAML/SMLMT, replay, LoRA, layer growth). Configs live under configs/ and launchers under script/.

bash
$ beetlelm-train --config_path configs/pico_default.yaml
$ beetlelm-train --config_path configs/quickstart_fineweb.yaml --validate_only

Some architectures need extra, non-PyPI dependencies (e.g. hnet needs mamba_ssm / flash_attn; DeepSpeed is Linux-only) — these import lazily, so the base install stays clean. Weights & Biases is forced offline by default; nothing phones home unless you opt in.

A fast, CPU-only smoke test trains the real model for a few steps and checks the loss is finite, that the model learns, that runs are deterministic, and that a loadable checkpoint is written: pytest -q tests/test_toy_smoke.py. See notebooks/quickstart.ipynb for a full walkthrough.

beetle-data

Prepare bilingual training data

beetle-data is a bilingual data-preparation pipeline for small language models: stream raw multilingual corpora (FineWeb-Edu / FineWeb-2 / CulturaX), decontaminate against evaluation benchmarks, score and filter, train BPE tokenizers, and pretokenize into Arrow/Parquet shards. It ships the full production code and a minimal, offline, reproducible path you can run start to finish in seconds.

1 · Install

bash
$ pip install beetle-data

…or from source. The core install is CPU-only; the heavy curriculum-mode stack is an opt-in extra.

bash
$ git clone https://github.com/beetlelm/beetle-data
$ cd beetle-data
$ pip install -e .                 # core pipeline (CPU)
$ pip install -e .[curriculum]     # + BeetleStream v2 GPU stack

2 · Quickstart (one command)

bash
$ beetle-data run --out-dir beetle_out

Runs the full pipeline on the bundled toy corpus (synthetic Spanish + English) with zero external downloads, writing:

  • beetle_out/tokenizer.json — the trained BPE tokenizer
  • beetle_out/pretokenized/es-en_train_0000.parquet — tokenized shards
  • beetle_out/stats.json — token/block/vocab statistics

Reproduce the toy artifact

With the default config you should see exactly these deterministic numbers:

The vocab is 468, not the requested 8000: the tiny corpus has fewer than 8000 learnable BPE merges, so training stops early — expected at toy scale. On a real corpus the vocab reaches the ceiling.

Pipeline steps as commands

The four core steps are also separate commands. Each falls back to the bundled toy corpus; point --data-dir at a folder of <lang>.txt files to use your own data.

bash
$ beetle-data build-corpus    --l1 es --out corpus.txt
$ beetle-data train-tokenizer --corpus corpus.txt --out tok.json --vocab-size 8000
$ beetle-data pretokenize     --tokenizer tok.json --corpus corpus.txt --out-dir shards --seq-len 128
$ beetle-data stats           shards

Python API

The same four steps are available from Python. See notebooks/quickstart.ipynb for inspecting and decoding the tokenized output.

python
from beetle_data import iter_bilingual, train_tokenizer, pretokenize, corpus_stats

tagged = list(iter_bilingual("es", "en"))      # [(text, "L1"|"L2"), ...]
tok = train_tokenizer((t for t, _ in tagged), vocab_size=8000)
stats = pretokenize(tagged, tok, out_dir="pretokenized", seq_len=128, lang="es-en")
print(stats["total_tokens"], stats["num_blocks"])

The full pipeline, at real scale

The production code streams raw corpora from Hugging Face and pretokenizes at billion-token scale (set HF_TOKEN first — no credentials are stored in the repo). Static mode runs three stages: benchmark index → stream + 13-gram decontaminate → pretokenize. BeetleStream v2 curriculum mode adds Stages A–D (teacher annotation, quality scoring, topic clustering, difficulty grading) and needs the GPU extra.

bash
$ python pipeline/run_pipeline.py          # full static pipeline
$ bash   scripts/launch_full_pipeline.sh    # cluster launcher
beetle-analyze

Analyse model evaluations

beetle-analyze is a minimal, reproducible toolkit for analysing language-model evaluation output via BLiMP-style minimal-pair accuracy. On top of the quickstart it ships a full research suite — CKA, probing, logit lens, sparse autoencoders (SAEs), MECO reading-time alignment, FLORES perplexity trajectories, and functional localization.

1 · Install

bash
$ git clone https://github.com/beetlelm/beetle-analyze
$ cd beetle-analyze
$ pip install -e .                 # core toolkit (CPU)
$ pip install -e .[eyetracking]    # + reading-time extras

Optional extras keep the heavy dependencies opt-in: [stats], [eyetracking] (minicons / wordfreq), [saes], [brain].

2 · Quickstart (BLiMP accuracy)

bash
$ beetle-analyze blimp
# overall minimal-pair accuracy: 0.6000
$ beetle-analyze blimp --scoring mean
# 0.80

Runs on the bundled toy data with zero downloads. Point --input at your own evaluation output and write results with --json-out / --plot-out; add --bootstrap for confidence intervals.

Run the full research suite

The master runner evaluates whole model families across languages, and the analyses are also exposed as console scripts (beetle-cka, beetle-probe, beetle-dev-trajectory).

bash
$ python analyze/run.py --all --family humanscale --langs deu nld zho eng
$ python analyze/run.py --all --family fineweb --langs deu nld
beetle-explorer

Explore models with no code

beetle-explorer lets you load and play with Beetle language models in Colab — no coding required. It is the non-technical companion to the training framework: open one notebook, pick a collection, language, curriculum, seed and checkpoint, move the sliders, and generate text.

Open the notebook

Everything lives in a single notebook — notebooks/Beetle_Model_Explorer.ipynb. Open it in Colab, run the setup cell, and choose a model from the dropdowns. It needs only torch, transformers, huggingface_hub and ipywidgets — no training stack.

python
from transformers import AutoModelForCausalLM
model = AutoModelForCausalLM.from_pretrained(
    repo, revision="step-N", trust_remote_code=True)

Open beetle-explorer

 Which collection to pick

When choosing a collection, the only genuine 24-billion-token models are Beetle-FineWeb-24B-4 and Beetle-FineWeb-24B-5. Because of a token-budget drift bug, some earlier collections were cut short:

  • Earlier "24B" collections (Beetle-FineWeb2-24B, Beetle-FineWeb3-24B) reached only ~3B tokens.
  • The earlier "2B" collection (Beetle-FineWeb-2B) reached only ~300M tokens.

For full-scale work, start with the final release. See the models page for the full explanation.

MECO — multilingual reading times

The Multilingual Eye-movement COrpus provides eye-tracking reading times for first- and second-language readers across many languages. Beetle uses it to test how well a model's surprisal predicts the time human learners actually spend reading each word.

meco-read.com

BLiSS — learner minimal pairs

BLiSS is a benchmark of learner-style minimal pairs for grammaticality and acceptability discrimination. Beetle uses it to measure whether models tell acceptable from unacceptable sentences in the way second-language learners do.

ALTACambridge/BLiSS

BabyLM 2025 2025.babylm-main.13

Related work from the Beetle authors on sample-efficient, developmentally-plausible language modelling. It motivates Beetle's controlled, small-scale training setup and the focus on how models learn under limited data.

aclanthology.org

EMNLP 2025 demo 2025.emnlp-demos.22

A system-demonstration paper for the tooling underpinning Beetle's controlled training and evaluation. It describes the infrastructure that makes reproducible, comparable model families practical.

aclanthology.org

CDL 2026 2026.cdl-1.15

Related work on cognitively-motivated and developmental language modelling. It connects model learning dynamics to patterns observed in human language acquisition — the broader research programme Beetle contributes to.

aclanthology.org
