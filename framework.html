Framework

A framework for studying language learning

Beetle provides an experimental framework for investigating how language models learn from linguistic experience. It brings together controlled training conditions, open model checkpoints, datasets, and evaluation tools to support systematic comparisons of learning trajectories.

🛠️ From using models to changing how they learn

The Beetle model suite lets you investigate models that already exist. The Beetle training framework lets you go further: design and run your own controlled experiments on how language models learn.

In conventional training, changing the curriculum can change other things at the same time, making it hard to say which factor caused a difference in behaviour. Beetle makes these comparisons systematic: you can manipulate the tokeniser, target language, training budget and language-exposure structure independently — and use the framework to reproduce our experiments, try alternative training strategies, or build new controlled model families.

Control the learning experience

Vary one aspect of training at a time

Beetle supports experiments that vary key aspects of training. Together, these dimensions allow researchers to investigate how different learning experiences affect linguistic behaviour and internal representations.

Language background

The language or languages a model learns.

Learning curriculum

How language exposure is distributed and ordered during training.

Data scale

The amount of training data available.

Training stage

The point in the learning trajectory at which a model is evaluated.

What can you do with the framework?

Turn a research question into a controlled experiment

🧪 Experiment with exposure schedules

Beetle uses five exposure curricula, B1–B5, to vary how and when a model encounters each language throughout training. Change when a language appears and investigate questions such as:

  • Does learning two languages simultaneously produce different representations from learning them sequentially?
  • What happens when a model meets its second language only after substantial experience with its first?
  • Does changing the distribution of languages across training affect which capabilities emerge?
  • Which exposure schedules best reproduce particular patterns of human language processing?

By comparing otherwise-matched models, you can investigate the effects of training history directly.

📊 Investigate the effects of training data

How much data does a model need, and does the order in which it sees that data matter? The framework supports experiments across different training budgets and data configurations.

  • Does a strategy that helps a smaller model remain beneficial at a larger scale?
  • Do different learning trajectories produce different outcomes under the same training budget?
  • How does a model's learning depend on the resources and experience available to it?

Study not only what a model learns, but how its learning depends on the data it is given.

🔤 Explore tokenisation and language

Tokenisation determines how text is split into the units a model processes — and different tokenisers can represent the same language differently, changing the inputs available during training.

  • Investigate tokenisation, language-specific representation and multilingual learning while holding other training choices fixed.
  • Ask whether alternative tokenisation changes how a model learns grammatical patterns.
  • Test how tokenisation affects the information a model transfers between languages.

Beetle's controlled approach separates tokenisation from the rest of the training pipeline.

🔬 Build controlled experiments of your own

The framework's value is in making it easy to create comparable models and test specific hypotheses about learning. Use it to:

  • Design experiments that vary one training factor at a time.
  • Train models with different language combinations and exposure schedules.
  • Compare models across training budgets and checkpoints.
  • Build matched baselines for new research questions.
  • Release your own controlled model families so others can reproduce and extend your work.

The key is that the differences between models are intentional, interpretable and scientifically useful.

From framework to scientific discovery

The framework and the model suite complement one another

Use the models to explore existing training trajectories, investigate internal representations, and reproduce analyses. Use the framework to change the training process, test new hypotheses, and generate models that answer questions the existing suite does not cover.

Together they support an iterative approach to research: start with an observation in an existing model, form a hypothesis about its training history, design a controlled experiment, and analyse the resulting models. Intermediate checkpoints make it possible to study not only what a model learns, but when particular behaviours emerge and how they change over training.

Ecosystem

Four small, focused repositories

Beetle is deliberately minimal and maximally forkable. Rather than one monolithic codebase, it is four small repositories you can read in an afternoon — each does one job well, and each has a step-by-step tutorial in the documentation.

beetlelm

The training framework

The core framework behind the released suite: the architecture zoo (with the PicoDecoder backbone), the modular tokeniser, the B1–B5 exposure curricula, and HuggingFace-compatible checkpoints. This is where models are trained.

Open repository  ·  Read the tutorial

beetle-data

The data pipeline

A minimal, reproducible bilingual data-preparation pipeline: build a corpus, train a BPE tokeniser, pretokenise into shards, and report stats — for small language models. This is where training data comes from.

Open repository  ·  Read the tutorial

beetle-analyze

The evaluation toolkit

A minimal, reproducible toolkit for analysing language-model evaluation output via BLiMP-style minimal-pair accuracy, with research tools for reading-time alignment, probing and representational analysis. This is where you measure what models learned.

Open repository  ·  Read the tutorial

beetle-explorer

The no-code companion

Load and play with Beetle language models in Colab — no coding required. A non-technical companion to the beetlelm training framework: pick a collection, language, curriculum and checkpoint, and generate text.

Open repository  ·  Read the tutorial
